# Bug 提交指南

简体中文 | [English](en/bug-reporting.md)

感谢帮助改进 Vexra。高质量 bug 报告应让维护者能够尽快复现、定位和判断影响范围。

## 提交前检查

- 确认问题不是未修复安全漏洞；如果可能涉及漏洞，请阅读 [安全策略](../SECURITY.md) 并走私有报告渠道。
- 尽量在相关的最新分支、最新发布版本或明确的提交号上复现。
- 搜索已有 issue，避免重复报告。
- 移除日志、截图和配置中的密钥、令牌、生产账号、私有仓库地址和敏感数据。

## 必填信息

请在 Bug report 表单中提供：

- Vexra 版本、依赖坐标、分支或提交号。
- 受影响模块，例如 `vexra-server`、`vexra-netty`、`vexra-adb` 或状态机插件。
- 使用路径，例如直接调用客户端 API、ADB/JDBC、gRPC、Netty、自定义 `SMPlugin` 或测试环境。
- 期望行为和实际行为。
- 最小复现样例，优先提供测试用例、命令序列或最小仓库。
- JDK、操作系统、Gradle、传输方式、集群节点数、LDB/存储依赖版本和关键配置。
- 最小必要日志、首个异常堆栈和错误输出。

## 并发、存储和一致性问题

如果问题涉及 Raft、事务、缓存、索引、磁盘存储、超时或网络重试，请尽量补充：

- 并发线程数、循环次数、失败频率和首次失败时间。
- 是否涉及事务、缓存、索引、浏览器访问、checkpoint/restore、repair/check 或 backup/restore 路径。
- 集群拓扑、leader 切换、网络断连、节点重启、快照安装或日志恢复事件。
- 失败前后关键数据状态、预期提交顺序和观察到的不一致现象。

## 复现样例建议

优先级从高到低：

1. 能直接加入仓库的失败测试。
2. 独立最小仓库或脚本。
3. 明确命令序列与配置片段。
4. 无法稳定复现时，提供日志、出现频率和最近一次完整环境信息。

## 安全边界

公开 bug issue 不应包含漏洞利用细节、攻击载荷、凭据、生产数据或未公开的系统拓扑。如果你不确定是否属于安全问题，请按安全问题处理，先走私有渠道或创建不含细节的占位 issue。
